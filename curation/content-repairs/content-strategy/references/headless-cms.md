# Content workflow and CMS requirements

Version-Timestamp: 2026-09-15T19:03:10.058784-04:00

Use this reference only when the requested strategy includes content operations or CMS selection. A topic plan does not require a platform migration.

Start with editor needs, current tools, approval roles, translation, preview, reuse, developer capacity, hosting constraints and maintenance budget. Reuse an adequate existing system. Separate content requirements from implementation choices.

Define only relevant content types and fields: for example, article title, body, author, publication status, factual sources and review date. Reusable approved testimonials or case studies should retain source and permission records. Preview access must not expose private drafts.

For public search pages, consider title, description, canonical URL and indexing controls. Character counts are editorial heuristics, not guaranteed search-display limits. Social-image requirements depend on destination.

When a platform decision is actually needed, verify current official documentation for the proposed edition and version: capabilities, pricing, roles, preview support, export, API limits and maintenance responsibilities. Do not infer plan entitlements from a generic comparison table. Record evidence and tradeoffs before recommending a migration.

Model draft, review and publication states to fit the team. A proposed workflow grants no publishing, permission-change or migration authority. Implementation belongs in the relevant project and must be verified there.
