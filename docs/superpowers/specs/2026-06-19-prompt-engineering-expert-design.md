# Design Spec — `prompt-engineering-expert`

Version-Timestamp: 2026-06-19
Author: New Minds Group (Daniel Gonell)
Status: Approved design → ready for implementation plan

---

## 1. Purpose

An original, portable, cross-IDE capability — built from the ground up — that helps
craft, improve, convert, debug, and operationalize prompts, system instructions,
agent definitions, and reusable AI-agent behavior. It is a new approach designed to
deliver the same high-leverage prompt-engineering capability inside any IDE
(Claude Code, Cursor, Codex, Antigravity) from one canonical source.

It must:

- Work **autonomously by default** — self-assess the project, infer intent, and
  produce a finished, usable prompt with stated assumptions in one pass.
- Support an **interactive mode on request** — a guided one-question-per-turn loop
  for collaborative refinement.
- Be **shareable across a team and multiple machines**.
- Start in **Claude Code**, then render to **Cursor, Codex, and Google Antigravity**
  from a single canonical source.

## 2. Scope decomposition

This is two sub-projects. Phase 1 is specced and built here; Phase 2 is designed
here and built next.

- **Phase 1 (this spec, build now):** the canonical skill + Claude Code agent +
  slash command, inside `ai-agent-skills-library`. Fully functional in Claude Code.
  This is the "brain."
- **Phase 2 (designed here, build next):** a standalone `prompt-engineering-expert`
  repo holding the portable skill at root plus per-IDE adapters (Cursor rule,
  Codex/AGENTS.md, Antigravity GEMINI.md) and team/multi-machine install. Phase 1
  is written so Phase 2 is packaging, not redesign.

## 3. Architecture — single source of truth

```
Canonical methodology (SKILL.md body)
        │  (loaded/applied by)
        ├── Agent wrapper (agents/prompt-engineering-expert.md)  — dispatchable subagent
        └── Slash command (/prompt-engineering-expert)           — explicit on-demand trigger
```

Exactly one place holds the methodology: the skill. The agent and the slash command
are thin wrappers that load and apply it. No duplicated logic → no drift.

### 3.1 Files (Phase 1, in `ai-agent-skills-library`)

| File | Role |
|------|------|
| `sources/original/skills/prompt-engineering-expert/SKILL.md` | The full canon (methodology + both modes). |
| `sources/original/skills/prompt-engineering-expert/references/model-guide.md` | Current cross-vendor task→model mapping (kept separate so it can be updated without touching the method). |

## 4. The canonical methodology (skill body)

### 4.1 Persona
A surgical prompt-engineering specialist. Plain, actionable language. Concise,
high-leverage improvements over theory.

### 4.2 The Prompt Blueprint (the spine)
Every drafted prompt is structured against these six sections unless the target
platform requires a different structure:

1. Role / Persona
2. Objective / OKR
3. Context
4. Requirements
5. Desired Output
6. Evaluation

### 4.3 Self-assessment protocol (runs before drafting)
On invocation, read available project context — files, `AGENTS.md` / `CLAUDE.md`,
`DESIGN.md`, recent work, the user's stated goal — to infer:

- What the prompt is **for** (task, deliverable, downstream consumer).
- **Target platform / runtime** (Claude Code agent, Cursor rule, a system prompt,
  an end-user chat prompt, etc.).
- **Target model** (and therefore context window + cost profile).
- **Audience, channel, stakes, acceptance criteria.**

Whatever can be inferred is **not** asked. Only genuinely output-changing unknowns
become questions.

### 4.4 Output pattern
Each response includes:

1. A tightened draft prompt in a single fenced code block.
2. A short rationale (1–3 bullets).
3. A `▸revisions` line — what changed since the last draft.
4. Model recommendation (≤2 sentences) when relevant.
5. Token budget note when the prompt is long / multi-document / near a context limit.

### 4.5 Token awareness + chaining
Estimate tokens per section + total for long prompts. Warn near common windows
(32k / 128k / 256k) about truncation, lost nuance, weaker reasoning, cost, harder
debugging. If estimated usage > ~60% of the likely window, propose a
map → select → reduce → synthesize chain with rough per-step budgets.

### 4.6 Safety + privacy
Follow safety policy. Refuse-and-redirect unsafe requests with a brief reason.
Never request secrets/keys/credentials/PII that aren't needed. If sensitive data
appears, mask it and proceed with placeholders.

### 4.7 Output destination
Default: return the prompt inline. On request, or when the prompt is clearly a
reusable asset, offer to save it into the project (e.g. `prompts/<name>.md` or into
`AGENTS.md`) with a `Version-Timestamp:` header per the attribution rule.

## 5. Operating modes

### 5.1 Autonomous-first (default)
Self-assess → draft the best-guess prompt against the Blueprint → state assumptions
explicitly → ask a clarifier **only** when a missing answer would materially change
the output. Produces a finished, usable artifact in one pass. If the user declines
questions or stalls, finalize with assumptions listed.

### 5.2 Interactive Wizard (on request)
Triggered by phrases like "take me through it step by step," "interactive mode,"
"ask me questions one at a time." Runs the one-question-per-turn loop:

- Exactly one clarifying question per turn (no compound/nested questions).
- Never repeats an answered question.
- Ends each turn with the action line: `[Run as-is] | [Ask next clarifier] | [Finish]`.
- Stops on "good enough" / "finalize" and emits a best-guess final prompt + assumptions.

## 6. Conversion support
Convert between formats while preserving intent, adapting (not copying) platform
specifics: Claude Code agent ↔ Cursor rule ↔ Codex/`AGENTS.md` ↔ custom GPT
instructions ↔ plain system prompt. This directly seeds Phase 2.

## 7. Model guidance
A **current, cross-vendor, task→model** mapping in `references/model-guide.md`:

- **Claude:** Opus 4.8 (hard architecture/strategy/deep reasoning), Sonnet 4.6
  (balanced agent/coding work), Haiku 4.5 (cheap classification/extraction/drafts),
  Fable 5 (latest family member — note current positioning).
- **OpenAI / Google:** current GPT and Gemini tiers, framed by task type.
- Framed as task → recommended model so it ages gracefully; the file carries its
  own `Version-Timestamp` and is updated independently of the methodology.

## 8. Triggering surfaces
- **Auto-trigger:** the skill `description` routes automatically whenever the user
  is writing/improving prompts, GPT/agent instructions, system prompts, or
  `AGENTS.md`. Trigger phrases embedded in the description.
- **Agent:** dispatchable subagent, tools `Read, Glob, Grep`, auto-routes on
  prompt-engineering keywords.
- **Slash command:** `/prompt-engineering-expert` for deliberate on-demand firing.

## 9. Phase 2 (designed, not built now) — cross-IDE standalone repo
Proposed standalone repo layout:

```
prompt-engineering-expert/
├── skill/SKILL.md            ← portable canon (identical methodology)
├── skill/references/         ← model-guide.md, blueprint.md
├── claude-code/              ← agent .md + slash command + install notes
├── cursor/                   ← .cursor/rules/*.mdc render
├── codex/                    ← AGENTS.md / codex agent render
├── antigravity/              ← GEMINI.md render (mind ~12k char/rule limit)
├── install.sh / install.ps1  ← team + multi-machine install
└── README.md                 ← per-IDE install + usage
```

Only platform-specific bits (tool names, the wrapper, file-location conventions)
differ between renders; the methodology is copied verbatim. To enable this, the
Phase 1 SKILL.md isolates platform specifics in a short "Platform adapter" section.

## 10. Engineering-mantra alignment
- **Security/privacy:** no secrets handling; mask-and-placeholder rule (§4.6).
- **Reliability:** single source of truth prevents drift across surfaces.
- **Compliance:** `Version-Timestamp` on saved artifacts and the model guide;
  attribution footer on commits.
- **Portability:** Agent Skills spec compliance keeps it cross-IDE.

## 11. Validation (definition of done for Phase 1)
- `./scripts/validate-frontmatter.sh` and `./scripts/validate-all.sh` pass.
- `ruby scripts/sync-skill-library.rb` regenerates `dist/` cleanly; `./scripts/check-generated.sh` passes.
- `ruby scripts/check-links.rb` passes.
- Skill auto-triggers on a prompt-writing request; agent dispatches; slash command fires.
- A smoke test: ask it to engineer one prompt autonomously, and once via the wizard.

## 12. Open items (resolve during planning)

- **O2 — exact `name`/`author` frontmatter** and whether to register the skill in

## 13. Out of scope (YAGNI)
- Building the Cursor/Codex/Antigravity renders now (Phase 2).
- Any runtime/telemetry for prompt quality scoring beyond the inline rubric.
- Auto-saving prompts without user request.
