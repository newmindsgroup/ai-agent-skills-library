# Memory vault mirror

Agent memory tends to accumulate in a place only the agent reads: a hidden directory, a SQLite file, an append-only JSONL log. That is fine until you want to search it on your phone, hand it to a teammate, or survive a dead disk. This skill turns any memory store into readable notes in a versioned vault, one way, without letting the mirror become a second source of truth.

## The shape of the thing

Three rules carry most of the value. Everything else is detail.

**One direction.** The memory store is the source. The vault is a projection. If someone can edit a mirrored note and have it matter, you now have two sources of truth and no way to reconcile them. Say so loudly in a README and in the frontmatter of every generated file, because a folder full of markdown in Obsidian is an _invitation_ to edit.

**Idempotent, byte-for-byte.** Running the sync twice in a row must leave the working tree clean. This sounds like polish; it is actually load-bearing. If every run dirties the repo, "you have uncommitted memory" stops being a signal and becomes noise, and the backup silently rots because nobody trusts the indicator anymore.

**Versioned somewhere private.** A mirror on the same disk as the original protects against nothing. Put the vault in a git repo with a remote. Check the repo is private _before_ the first push, because memory stores routinely contain home addresses, client names, credentials-adjacent detail, and personal drafts.

## When not to do this

Check this before building anything. A mirror is cheap to add and expensive to remove, because once it exists people start linking to it.

**The project already has a memory layer that would be duplicated.** Some mature projects accumulate several: a curated docs directory, a committed knowledge graph, a working graph, decision records, and the agent's own store. Adding a mirror there does not create a new capability, it creates a sixth thing to keep in sync and a second place to look. Count the existing layers first and ask which one the mirror would _replace_. If the answer is none, do not build it.

**A useful governing rule**, borrowed from a project that got this right: if a fact can be regenerated by re-running a tool, it does not belong in an authored vault; if it required judgment, it does. A memory mirror is regenerable by construction. That makes it a fine _indexed_ layer and a bad _authored_ one. Keep it in its own clearly-marked folder, never interleaved with hand-written notes.

**The vault has an isolation constraint.** If a project's vault is deliberately scoped (client work that must not touch personal notes, or vice versa), a mirror that drags in a general-purpose memory store violates it. Ask what the vault is _not_ supposed to contain.

When the answer is "don't mirror", the useful deliverable is usually an index or a pointer, not a copy.

## When the mirror should become the source

A one-way mirror assumes exactly one writer. Once a second tool needs to _write_ memory (moving a project from one coding agent to another, or running two side by side), the mirror is the wrong shape. The second tool's learnings have nowhere to go, or they land in its own private store and never reach the vault.

Flip it instead. Make the vault folder the store, and point each tool's native memory location at it:

```bash
cp -p "$NATIVE"/*.md "$VAULT/Memory/"     # seed, then verify checksums as in step 5
bak="$NATIVE.pre-ssot-$(date +%Y%m%d)"
mv "$NATIVE" "$bak"                        # keep the original until proven
ln -s "$VAULT/Memory" "$NATIVE" || mv "$bak" "$NATIVE"
```

A tool that cannot follow a symlink, or keeps a global memory across projects, gets an instruction in the project's agent file instead: read the index at session start, write new entries here.

Three checks before calling it done:

- **Confirm the tool reads through the link,** not just the OS. A harness file-change notification after an edit made through the symlink is good evidence.
- **Watch for the native folder coming back.** A reinstall or restore can put a real folder in place and quietly split memory into two stores again. Have the session-end check warn when the path is no longer a link.
- **Symlinks travel.** If the native store sits inside a config repo that other machines pull, committing the link points every machine at your absolute path. Each machine then needs the vault repo cloned at the same location.

Then retire the old mirror folders. Leaving them in place recreates the duplicate described above.

## Workflow

### 1. Find out what you actually have

Do not assume the store is what the docs say. Locate it, count the entries, and check whether it is already backed up.

**Check that the store is live, not just present.** Find out who writes it and when it last changed. A database with no remaining writer is a snapshot, however authoritative its docs say it is, and mirroring it faithfully reproduces stale data. When two candidate sources disagree, compare last-write times and look for the append-only log the running system actually writes before deciding which one is wrong. Getting this backwards means retiring the correct mirror and keeping the stale one.

```bash
stat -c '%y %n' store.db events.jsonl            # which one moved recently?
grep -rl 'INSERT INTO' scripts/ | head           # does anything still write the db?
```

```bash
git -C <repo> check-ignore -v <memory-path>   # is it excluded?
git -C <repo> ls-files --error-unmatch <file> # is it tracked?
tmutil destinationinfo                        # any machine-level backup at all?
```

An entry that exists on disk but is absent from the index never gets recalled, so it is functionally deleted while still taking up space. Diff the two:

```bash
ls *.md | grep -v '^INDEX.md$' | sort > /tmp/ondisk
grep -o '(\([a-z0-9_]*\.md\))' INDEX.md | tr -d '()' | sort -u > /tmp/indexed
comm -23 /tmp/ondisk /tmp/indexed   # orphans: on disk, unreachable
comm -13 /tmp/ondisk /tmp/indexed   # broken links: indexed, missing
```

Orphans are usually superseded versions. Do not silently delete them; add a "Superseded" section to the index so everything on disk is reachable from it, and note which entry replaced which.

### 2. Pick the transport

Prefer the boring one. A pull over an SSH key you already trust beats a sync daemon: one moving part instead of a daemon on each end, a pairing step, and an open port. Reach for continuous sync only when you genuinely need sub-minute propagation or bidirectional edits, which a receive-only mirror by definition does not.

For a remote store, stage the pull to a temp file first so a mid-transfer failure cannot leave a half-written mirror, and refuse to proceed on an empty pull rather than wiping the vault:

```bash
ssh -o BatchMode=yes -o ConnectTimeout=15 "$HOST" "cat '$REMOTE'" > "$STAGE" || die "..."
[[ -s "$STAGE" ]] || die "pulled an empty log, refusing to wipe the mirror"
```

### 3. Replay, do not copy

If the store is an append-only event log, the records are _events_, not memories. Copying every record produces a mirror where deleted memories come back and real ones are buried under read receipts. Replay the log into current state instead. See `references/event-replay.md` for the full semantics and a worked example.

If the store is already one-file-per-memory, `rsync` is enough, but read the filter gotchas below before writing the flags.

### 4. Generate notes plus an index

Each note gets frontmatter carrying provenance: source id, type, created date, tags, and a `mirrored_from` pointing at the origin. Provenance is what lets a reader tell a mirrored note from something they wrote.

The index is where the mirror earns its keep. Convert the store's own index into wikilinks so the whole memory graph becomes clickable:

```bash
sed -E 's/\[([^]]+)\]\(([a-zA-Z0-9_.-]+)\.md\)/[[\2|\1]]/g' INDEX.md
```

Leave links containing a slash alone. Those point outside the mirror and a wikilink would break them.

### 5. Verify before you destroy

If this replaces an existing location, copy, verify, _then_ remove. Never `mv` the only copy of something that exists to prevent data loss.

```bash
cp -R "$SRC" "$DST"
a=$(cd "$SRC" && find . -type f -exec shasum {} + | sort -k2 | shasum)
b=$(cd "$DST" && find . -type f -exec shasum {} + | sort -k2 | shasum)
[ "$a" = "$b" ] || die "checksum mismatch, not removing source"
```

For a move into a repo, verify the content reached the _remote_ before deleting the original. A local commit is not a backup:

```bash
git ls-tree -r --name-only origin/main -- <path> | wc -l
git cat-file -p origin/main:"<path>/<critical-file>" | wc -c   # bytes, not just the name
```

## Gotchas that cost real time

These are the failure modes that look like success, which makes them expensive.

**rsync applies the first matching filter rule.** `--include='*.md' --exclude='FOO.md'` does not exclude `FOO.md`, because the include already matched. Excludes go first:

```
--include='*/' --exclude='INDEX.md' --exclude='_Index.md' --include='*.md' --exclude='*'
```

**`--delete` eats files you generate in the destination.** A generated `_Index.md` has no counterpart in the source, so it matches the include and gets deleted every run, then recreated. Nothing is lost, so it is easy to miss, but the file is rewritten every time and the vault is permanently dirty. Exclude generated files explicitly.

**A timestamp in generated output defeats change detection.** If the header carries a `Version-Timestamp`, every run differs and every run dirties the repo. Compare the body only and leave the file untouched when nothing changed:

```bash
strip='1,/^---$/d; 1,/^---$/d'   # drop the frontmatter block, compare the body
if [ "$(sed "$strip" "$new")" = "$(sed "$strip" "$existing" 2>/dev/null)" ]; then keep; else replace; fi
```

**An Obsidian MCP is bound to one vault.** The Local REST API plugin runs per-vault. A write aimed at a vault that lacks the plugin lands in whichever vault _does_ have it, and returns success. If the target vault has no `community-plugins.json`, the MCP cannot reach it at all. Use filesystem writes against the absolute path, and record the trap somewhere the next session will read.

**Uncommitted memory is unbacked memory.** Tracked in git is not the same as pushed. Check for uncommitted entries as part of the sync and surface the count.

**macOS ships bash 3.2.57, and bash 4 features fail there quietly.** `/bin/bash` on macOS is from 2007 for licensing reasons, and `mapfile`, `readarray`, `declare -A`, and `$'\uXXXX'` escapes either error or silently degrade. A script that has "always worked" in testing may never have actually run. Under `set -u`, bash 3.2 is also stricter about empty-array expansion, so exercise the zero-element and one-element paths, not just the happy path:

```bash
/bin/bash script.sh              # not `bash`, which may resolve to a newer build
```

## Automating it

A session-end hook is the natural trigger, since that is when new memory exists. Two cautions.

Do not auto-commit. A blind `git add` at session end sweeps up whatever else is in the tree, including another session's in-flight work. Sync, then _report_ whether the vault is dirty, and let a human commit.

Installing a hook runs arbitrary shell automatically, so expect it to require explicit user approval. Hand the user the config rather than assuming you can write it.

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "timeout": 60,
            "command": "bash ~/path/sync.sh >/dev/null 2>&1 || exit 0; ..."
          }
        ]
      }
    ]
  }
}
```

The command should emit `{"systemMessage": "..."}` on stdout to surface its result.
